## Commit 1: #11 — Hook Card / Caption Dedup

### Problem

During the first ~3 seconds, the viewer sees duplicate text:
1. CardGenerator bakes hook text into 1080×1920 PNG (big, styled headline)
2. `build_keyword_captions()` draws the same keywords as a floating caption at the bottom

### Solution

Skip keyword captions during the hook card's duration. The card already displays the text.

### Changes

**`rendering/subtitle_engine.py`** — `build_keyword_captions()`:
- Add `hook_duration: float = 0.0` parameter
- Skip any caption where `start_time < hook_duration`

**`agents/composer.py`**:
- When calling `build_keyword_captions()`, pass first clip's `target_duration` as `hook_duration`

### Tests

- Update existing `test_build_keyword_captions_*` tests to verify hook window skip
- Verify captions after hook window appear normally

## Commit 2: #6+#9 — Config Overhaul (Merged)

### Problem

- `config/hierarchy.py` defines per-agent model/temperature/max_tokens but no file imports it
- 5 agents hardcode all values directly in LLM calls
- `max_tokens` values are guesses that cause truncation (segment_producer 1024 → story_beats=[])
- No auto-determination from model capabilities

### Solution

Single source of truth: hierarchy preset → OpenRouter model metadata → .env overrides.

### 2a. New: `config/model_cache.py`

```python
# Public API:
get_model_metadata(model_name: str) -> dict | None
    # Returns {"context_length": int, "max_completion_tokens": int, ...}
    # Lazy-load on first call, auto-refresh every 7 days
    # Free API: GET https://openrouter.ai/api/v1/models

refresh_model_cache(force: bool = False) -> None
    # Fetch, parse, write to data/model_cache.json
    # Skip if cache < 7 days old unless force=True
```

Cache location: `data/model_cache.json`  
Refresh: 7-day TTL, or on force refresh  
Error handling: if API unreachable, use cached data (even if stale). If no cache exists, log warning and return None (agents fall back to model defaults).

### 2b. Update: `config/hierarchy.py`

Remove `max_tokens` from `AgentDefaults.PRESETS`. Only `model` + `temperature` remain:


### 2c. Update: `config/loader.py` — new `get_agent_config()`

```python
def get_agent_config(agent_name: str) -> dict:
    """Resolve agent config: hierarchy preset → model metadata → .env overrides.
    
    Returns: {"model": str, "temperature": float, "max_completion_tokens": int | None}
    """
```

Resolution chain:
1. Base values from `ConfigHierarchy` (model, temperature)
2. Model metadata from cache → `max_completion_tokens`
3. `.env` overrides via existing `AppSettings` fields (`safety_model`, etc.)

### 2d. Update: `llm/client.py`

- Make `max_tokens` optional (default `None`)
- When `None`, don't send the param — model uses its own max
- Add `reasoning_effort: "none"` to every request body
- Rename internal param to `max_completion_tokens` (OpenRouter preferred)

```python
def chat(
    self,
    model: str,
    messages: list[dict[str, str]],
    temperature: float = 0.7,
    max_completion_tokens: int | None = None,
    **kwargs: Any,
) -> dict[str, Any]:
    body = {
        "model": model,
        "messages": messages,
        "temperature": temperature,
        "reasoning_effort": "none",  # Always disable thinking
    }
    if max_completion_tokens is not None:
        body["max_completion_tokens"] = max_completion_tokens
```

## Commit 3: #7+#8 — Logging Improvements (Merged)

### 3a. Per-Job Log Files (#7)

**`core/logging.py`** — add:

```python
def add_job_file_handler(job_id: int, logs_dir: str = "logs") -> None:
    """Add FileHandler writing to {logs_dir}/run-job_{job_id}.log."""

def remove_job_file_handler() -> None:
    """Remove job-specific FileHandler from root logger."""
```

- File path: `logs/run-job_{job_id}.log`
- Captures everything that goes to stderr (same format, same level)
- Format matches stderr: `%(asctime)s [%(levelname)-5s] %(name)s: %(message)s`

**`orchestrator/engine.py`**:
- After `create_job()` → call `add_job_file_handler(job_id)`
- Before return from `run_pipeline()` → call `remove_job_file_handler()`

### 3b. Third-Party Log Tagging (#8)

**`core/logging.py`** — add:

```python
class ThirdPartyLogFilter(logging.Filter):
    """Prepend [LIB] to third-party logger output for visual filtering."""
    THIRD_PARTY_PREFIXES = ("httpcore", "httpx", "urllib3")
    
    def filter(self, record: logging.LogRecord) -> bool:
        if any(record.name.startswith(p) for p in self.THIRD_PARTY_PREFIXES):
            record.msg = f"[LIB] {record.msg}"
        return True
```

Apply to all handlers in `setup_logging()`.

### Output Example

```

14:23:01 [DEBUG] [LIB] httpcore.connection: connect_tcp started
14:23:02 [INFO ] clipper_agency.llm.client: LLM response: model=mimo-v2-flash...
```

## Commit 4: #10 — TTS Chunking Safety Net

### Problem

No fallback when script text exceeds TTS provider char budget. Currently: silent truncation or failure.

### MVP Context

TikTok ≤60s → ~150 words → ~1,000 chars → well under ALL provider limits. Chunking rarely fires but must exist.

### 4a. Expose char limits from services

| Service | Constant | Value |
|---------|----------|-------|
| `services/elevenlabs.py` | `CHAR_LIMIT` | 10,000 (Multilingual v2) |
| `services/gemini_tts.py` | `CHAR_LIMIT` | 5,000 (practical) |
| `services/fish_audio.py` | `CHAR_LIMIT` | 5,000 (placeholder) |

`voice_producer.py` gets `_PROVIDER_CHAR_LIMITS` dict mapping provider name → limit.

### 4b. Chunking functions in `voice_producer.py`

```python
def _chunk_text(text: str, chunk_size_words: int = 250) -> list[str]:
    """Split text at sentence boundaries into chunks of ~chunk_size_words."""

def _generate_chunked_voiceover(
    self, text: str, voice_id: str | None, job_id: int,
    assets_cache: str, provider: str,
) -> dict[str, Any]:
    """Generate audio per chunk, concat, stitch timestamps."""

def _concat_audio_chunks(self, chunk_paths: list[str], output_path: str) -> str:
    """FFmpeg concat demuxer — no crossfade (voice only)."""

def _stitch_timestamps(
    self, chunk_timestamps: list[list[dict]], chunk_durations: list[float]
) -> list[dict]:
    """Merge per-chunk timestamps with cumulative audio offsets."""
```

### 4c. Wire into existing flow

In `_generate_continuous_voiceover()`, add pre-flight check:

```python
char_limit = _PROVIDER_CHAR_LIMITS.get(provider, 5000)
if len(text) <= char_limit:
    # DEFAULT PATH — single call (unchanged, zero overhead)
    result = self._try_provider(...)
else:
    # FALLBACK — chunked generation
    logger.warning("Voice: text (%d chars) exceeds %s limit (%d), chunking",
                   len(text), provider, char_limit)
    result = self._generate_chunked_voiceover(text, ...)
```

### Chunking Algorithm

1. Split text at sentence boundaries (`.`, `!`, `?`)
2. Target ~250 words per chunk (safe for all providers)
3. Generate audio per chunk → `chunk_001.mp3`, `chunk_002.mp3`, ...
4. FFmpeg concat demuxer → single audio file
5. Stitch timestamps: add cumulative chunk duration offset to each chunk's word timestamps

### Tests

- Unit test `_chunk_text()` — sentence boundary splits, respects word budget
- Unit test `_stitch_timestamps()` — cumulative offset math correct
- Unit test `_concat_audio_chunks()` — mock FFmpeg, verify command structure
- Integration: short text → verify single-call path unchanged
- Integration: long text → verify chunked path produces valid output
