# ADR 0026: v2.4.0 Production Correctness — Enforce Contracts, Don't Rebuild

**Date:** 2026-06-15
**Status:** Accepted
**Phase:** 26

## Context

After PR #48 (Composer probe blocker fix) and PR #49 (dead `multimodal_provider`
removal), a production correctness audit of the `master` branch (v2.3.0) revealed
**four confirmed defects** where existing infrastructure was solid but contracts
were not enforced. An external plan review (ChatGPT) independently reached the same
conclusion; both analyses agree the infrastructure is built — the problem is wiring
and enforcement.

### The four confirmed defects (verified against code)

1. **Rejected candidates leave the original action in the plan.**
   `VisualDirector._apply_best_candidate()` (`visual_director.py:997`) only replaces
   `plan_item["action"]` when `best.decision == "accept"`. When all candidates are
   rejected, the LLM-selected original action survives unqualified and gets rendered.

2. **Two independent beat-duration derivations produce different timelines.**
   `VisualDirector._calculate_beat_durations()` (`visual_director.py:263`) searches
   voice timestamps. `Composer._compute_beat_durations()` (`composer.py:1255`)
   independently re-derives durations from `narrative_structure.word_range`. They
   drift. This is exactly the symptom of **ADR 0020 (canonical timeline) being
   "Proposed" but never enforced.**

3. **`fade_to_black` fade-out starts at `st=0.0` instead of clip end.**
   `TreatmentFilterBuilder.build()` (`treatment_filters.py:19`) defaults
   `start_time` to `0.0`. Both Composer call sites (`composer.py:1016, 1398`) omit
   the argument, so fade-out filters substitute `st=0.0` — fading out at the clip
   start, not end.

4. **Deterministic gate failures cannot reach the existing repair loop.**
   `_handle_review_outcome()` (`engine.py:264`) only enters the repair loop when
   `review_output["repair_plan"]` exists with patches. `repair_router.route_repair()`
   already knows `black_frame → composer`, `freeze_frame → composer`, etc. — but
   deterministic gates don't auto-generate `RepairPatch` objects. The LLM reviewer
   must decide to create them, and often doesn't. Result: deterministic failures go
   straight to `manual_review_required`.

### What is already built (verified — do NOT rebuild)

Per AGENTS.md (phases 21–24) and grep confirmation: multi-provider Segment Producer
discovery, source-quality tiers, OCR/face/cleanliness inspection, multimodal candidate
inspection, Composer black/freeze/empty diagnostics, Reviewer deterministic gates,
bounded repair-loop infrastructure (`repair_router` + `repair_metrics`), lifecycle
statuses, and LLM tracing for all agents. ADR 0020 (canonical timeline) and ADR 0023
(repair routing) exist as architectural decisions but are not fully realized in code.

## Decision

**Adopt a contract-enforcement approach for v2.4.0: fix broken contracts and make
existing infrastructure reachable, rather than building new subsystems.**

Concretely:

1. **Enforce ADR 0020** — make the canonical beat timeline the single source of
   truth. Both Visual Director and Composer read one immutable timeline; remove
   competing duration derivations. ADR 0020 status moves Proposed → Implemented.

2. **Extend ADR 0023** — make deterministic gate failures auto-generate
   `RepairPatch` objects with correct `reason` + `rerun_from`, so the existing
   repair loop fires automatically. No new repair engine.

3. **Enforce candidate rejection** — when all candidates are rejected, clear the
   original plan action rather than leaving it in place.

4. **Introduce a pre-Visual-Director asset qualification boundary** — the genuinely
   new architectural element. Inspection modules (frame sampler, OCR, face detector,
   source cleanliness, multimodal inspection, semantic ranker) currently live *inside*
   Visual Director. Move/expose them as a qualification service that runs *before*
   VD, so bad sources are rejected before the LLM plans visuals around them.

5. **Defer the version bump** — v2.4.0 is cut only after all P3 work (release gate)
   passes. No intermediate version bumps; each PR targets `master` at v2.3.0 until
   the final release PR.

## Alternatives Considered

### Rebuild subsystems from scratch

- **Pros:** Clean slate, no legacy constraints.
- **Cons:** Violates KISS/YAGNI (AGENTS.md). Discards 1900+ passing tests and
  proven modules. Massive scope expansion. The infrastructure isn't the problem —
  the contracts are.
- **Rejected.**

### Leave bugs, only add new features

- **Pros:** Faster short-term velocity.
- **Cons:** Production correctness defects compound. Job #8 already demonstrated
  rejected assets being rendered and timelines mismatching. Each new feature built
  on broken contracts inherits the defects.
- **Rejected.**

### Fix bugs only, defer architectural changes

- **Pros:** Lowest risk.
- **Cons:** Bug 2 (competing timelines) is architectural — patching one derivation
  without consolidating guarantees recurrence. Bug 4 (repair unreachable) is also
  architectural — adding repair plans ad hoc per gate doesn't scale.
- **Partially adopted:** PR 1 fixes the 4 immediate bugs with minimal scope;
  PRs 2–3 address the architectural roots.

## Rationale

- **The codebase already has the right modules.** Phases 21–24 built comprehensive
  inspection, ranking, repair, and quality-gate infrastructure. The defects are
  contract gaps, not missing features.
- **ADR 0020 and ADR 0023 are unfulfilled.** Both decisions were correct but never
  fully implemented. Phase 26 completes them.
- **Evidence-based:** all four defects were verified against current `master` with
  specific file/line references before this ADR was written.
- **KISS:** fixing contracts is cheaper and safer than rebuilding subsystems.

## Consequences

- **Positive:** Existing 1900+ tests and proven modules are preserved.
- **Positive:** ADR 0020 and ADR 0023 are finally realized, not just proposed.
- **Positive:** Production correctness defects from Job #8 are addressed at the root.
- **Negative:** Pre-VD qualification (PR 5) is the highest-risk change — it refactors
  a working pipeline. Requires strong integration test coverage before merging.
- **Negative:** Some agent contracts change (VD reads timeline instead of deriving;
  Composer reads timeline instead of deriving).
- **Neutral:** Version stays v2.3.0 until all P3 work lands; the bump is the final
  release step, not an intermediate one.
